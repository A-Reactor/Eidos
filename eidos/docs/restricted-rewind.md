# 循环与受限回溯

“循环与受限回溯”适合主角有回到过去的能力。玩家可以回看经历，但实际发动由游戏根据剧情判断；回看、世界线浏览、行动记录前后翻页都不会替角色发动能力。普通世界仍保留原有自由回档。

## 作者配置

新建世界选择内置“循环与受限回溯”（loop-manager），让世界生成描述能力的触发条件、目标范围与代价。作者也可在既有世界的 gameModeConfig 加入：

```json
{
  "rewind": {
    "anchorLabels": ["黎明醒来"],
    "requires": { "gameplay.loop-manager.ready": true },
    "memory": { "maxChars": 12000, "recentFullNodes": 2 }
  }
}
```

标记是可选的定位提示，不是可用目标白名单。未标记的过去节点也能成为目标；模型依据作品能力和实际剧情判断。仅当作品规定固定锚点时，模型才按固定锚点选择。实际到达锚点的行动摘要使用 `[LABEL:黎明醒来]`；节点存有快照才可恢复。旧节点仅在摘要含标签时也能识别。目标必须在当前祖先路径中，不能跳入尚未经历的旁支或当前节点本身。旧配置 `loopAnchorNodeLabel` 兼容；`loopAnchorScene` 只匹配开场根节点，不把同地点的后续访问混成同一时刻。

`requires` 使用当前世界标记的完整名称，允许作者自己的玩法规则管理。内置规则 `allow-rewind` 设置 `gameplay.loop-manager.ready=true`，`close-rewind` 将它关闭。模型依据实际剧情决定是否提议这些事件，程序仍检查规则和标记。新内置包未显式写 requires 时也使用这道许可；旧版无规则的循环包继续按游戏的回溯请求判断。作者显式给出空 requires 时仅依赖剧情判定，不额外要求标记。`enabled:false` 暂时关闭能力，配置无效时也不会退回自由回档。

游戏真正发动时，在本次已执行行动的 worldImpacts 中提议 `[BACKTRACK:真实节点ID] 具体发动原因`。许可事件与请求可在同轮产生。玩家说“回溯”不是许可；第三人称、内省和结果补写都不能触发。主角能力的语义判断仍由模型／作者规则负责，宿主负责目标、条件、保存和请求归属的检查。

## 历史原文工具

正常行动需要核对旧事或定位目标时，模型可以先只输出 `{"historyRequest":{"query":"检索词"}}`，再用 `{"historyRequest":{"nodeId":"真实节点ID","offset":0}}` 阅读原文。搜索结果含 ID、父节点 ID、步数、游戏时间和片段。query 为空时浏览历史索引，搜索结果同样支持 nextOffset 分页；也可沿 parentId 向前查阅。单页最多 12000 字符，返回 `nextOffset` 时可继续读取，直到获得需要的细节；不依赖固定字数的自动摘录。

工具范围是当前经历的已展示正文以及回溯记忆带回的来源节点。未经历旁支、主角未知的旁观秘密、尚未展示的正文不在范围内。查询和读取不会执行行动、推进时间或触发插件事件；最终正常行动才进入结算。取消或切换进度会丢弃未结算结果，已发生的模型用量仍记录。重复请求同一页或单轮超过八次查阅会终止本轮，保留当前进度。

这是通用的历史查阅能力，不为“回到某一时间”等措辞单独增加命令。模型通过原文判断事件先后和目标，最终使用真实节点 ID。宿主恢复的是实际已保存的节点快照。

## 经历如何保留

触发行动先完整保存，再在目标之后新建到达节点。旧未来和原目标不被改写。世界、时间、物品、任务及 NPC 恢复目标快照；只有主角独立记忆累积，不整份搬运未来百科、NPC 心理或背包。

压缩使用每步已有行动摘要与正文句，近期给予更多原文空间，较早经历均匀压缩。`maxChars` 是字符预算，默认 12000，可在 1000–40000 之间调整；`recentFullNodes` 默认 2，可在 0–8 之间调整，预算足够时保留近期全文，预算不足时近期获得更多空间。这是有损的离线压缩，不声称与模型语义总结等价；没有逐次新增模型调用。所有实际正文仍保留在旧分支，记忆携带来源节点，回忆检索可以重新找到细节。

压缩记忆标明“旧未来”，不表示本轮已发生，也不让其他角色知道。旁观镜头不会进入主角回溯记忆。不强制“既视感”或失忆，作品可以让主角清楚记得每一轮。

记忆随快照、普通存档和世界线导出保留。完整世界线备份包含旧分支原文；只导出单个复现场景或只导出局部子树时，保留压缩记忆，但其范围以外的旧原文需要完整备份才能检索。存档管理仍可按玩家意愿加载；这不是防修改或禁止读档的铁人模式。

## 验收建议

1. 让角色获得一条信息，再满足作品设定的触发条件。回溯后世界回到过去，主角可以使用记忆，NPC 不应自然知道旧未来。
2. 回看旧分支全文，再返回游戏，位置、时间和进度应保持当前循环。
3. 尝试未许可、不存在的目标或未经历旁支；游戏应拒绝实际跳转，保留当前进度。
4. 连续回溯两次并保存、加载，确认主角经历累积。是否满足文学表现与剧情条件，由实际模型游玩验收。
