# 文字地图与角色扮演

中文屋（稳定 ID `chinese-room`）只把主界面的文字画面替换为可走动的地图。原有记录、对话、输入、背包、任务、菜单、时间与存档保持使用原游戏组件和逻辑，地图里不添加第二套面板、行动列表或方向按钮。

导入 `mods/dist/chinese-room.eidos-plugin.json` 后在创建世界时选择。当前地点先有基础地图，缺少有效地图文件时，首次进入或公开人物、出口变化可用设置里的分析模型补绘并计入用量。绘制期间可以继续走动；失败保留原图，不在每句对话后反复收费重试。原有“模组设置”里可关闭自动绘制；重新开启或改变地图画面风格可重新绘制，无需主界面工具栏。

## 操作

- 方向键：移动与转向。未被宿主快捷键占用的 WASD 也可移动；默认 A/S/D 用于状态、世界线、图库。碰到人物停在面前，不自动开口。
- 设置中的“下一段 / 确认”（默认 Z）/ 回车 / 空格：与面前相邻对象交互；对话未读完时沿用原阅读流程继续。其他宿主快捷键在地图内同样生效。
- 点击人物、物件、出口：沿可达路线走近，再交互。移动到出口时使用主游戏的前往地点行动。用 Tab 聚焦地图对象后，回车／空格也可执行该对象的点击交互。
- 地图外的阅读空白区域（包括行动记录留白）可继续下一段；点选正文后仍可使用原来配置的阅读快捷键。输入框、选中文本和菜单拥有优先权，不会误触地图或翻页。
- Esc：停止自动走动或当前地图绘制。原菜单、背包与输入继续通过原界面使用。
- 普通格内移动不推进时间、不消耗行动次数、不调用叙事，也不创建世界线节点。对话和调查期间锁定移动。

当前场景的人物、已发现线索、已知通路来自主世界。地图交互通过 `Eidos.world.interact` 进入正常玩家行动管线，人物反应、物品去向、目标与新地点仍由主游戏处理。地图只保存空间布局与局部坐标，不拥有独立 NPC、背包、任务、奖励或战斗。

地图按地点逐步生成与缓存；相机最多显示附近 17×11 格；字号变大或记录区占用更多空间时，会减少附近可见格数，保持字格清楚，而不是把整图挤小。地图继承宿主字号和主题；对白、地图、记录与输入区按实际尺寸避让。更大的地图随角色移动。进入地点时尽量从对应的返回出口附近出现，回溯则恢复快照中的位置。生成期间切换分支或暂停会停止旧请求，迟到结果不采用。绘制和交互错误使用原有通知组件反馈。

## 随剧情更新地图（0.4）

主叙事模型现在可以复用已有文件工具。目录里的 `maps/<插件ID>/current.json` 是只读的当前布局、公开场景与主角坐标，需要空间信息时才读取。普通对话不重画地图；环境确实变化时，以原图为基础做局部修改，保留地标、入口与活动空间。

新地图沿用 `eidos-scene-map` v1，通过正常 `documents` 输出，`key` 使用 `scene_map` 或 `scene_map_` 加字母数字后缀，`format: "text"`。正文可直接是完整 JSON，也可用 `artifactRef` 引用本轮工具制作的草稿；`segmentIndex` 关联变化发生的段落，无需在故事中展示文件链接。宿主接受行动并播放合并该文件后，地图才可采用，不读取未播放的候选。当前界面已经公开的对象可随对应段落更新；新人物或新地点等到场景公开后再出现。

有效文件优先于单独的分析绘图，同一布局不会再额外调用模型。无效引用、不可达对象、占住主角的位置或迟到的旧分支结果不采用，继续保留原图。地图与文件版本仍随普通快照和分支恢复。生成的地图文件可在原有文件界面查阅，不增加地图专属面板。

宿主向地图提供 `context.sceneMapFiles`（当前分支已播放的地图文件目录）及只读 `Eidos.world.files.read(path, version)`。只允许读取这个目录中的实际版本，不是任意工作区访问权限。其他玩法模组的私有文件、未来文件和角色文件授权不受影响。

## AI 地图设计

[map-design.js](map-design.js) 是实际发送给模型的指南，[map-design.md](map-design.md) 记录 GitHub 参考来源。指南要求先安排地点功能、地标、出入口和动线，再组织地形；区分自然与人工空间、为人物交谈留出位置、保持回访一致。文字是地形与角色的视觉材料，地面留白，重要对象才突出。

`protocol.js` 校验 `eidos-scene-map` v1：sceneId 对应当前真实地点，tiles 定义单字地形与可行走性，rows 为等宽地图，entry 为入口，entities 的 npc/exit/object/action 引用当前人物、通路、已发现线索或实际 availableActions。所有对象须可接近，入口和实体不能重叠，重绘不能堵住主角。

`engine.js` 处理基础布局、碰撞、寻路、朝向、镜头和主世界对象同步；`generation.js` 维护数据输出契约；`view.js/ui.js` 只负责地图及操作。`ui.presentation=scene-map` 告诉宿主保留原记录和对白，仅替换中央文字画面。主题实时继承宿主背景、字体、字号和强调色。对话中途读档仍显示已保存的地图，打开快捷菜单时保留画面并暂停地图操作。

打包：`node scripts/pack-mods.mjs chinese-room`。`npm run dev:mods` 可在原游戏外壳预览；固定响应只能检查操控与展示，真实模型的地图设计与叙事质量仍需实际游玩验收。地图生成遵循已有分析模型与材料接口能力。
