# 篇章叙事 1.0.0

把同一世界里的主线、人物关系、地方事件、活动和日常组织成可持续发展的篇章。KEI 根据已发生经历和本次行动准备当前章；ALICE 写具体场面。章纲可以修订，玩家可以离开、提前解决、拒绝或改变目标。

## 使用

使用包含篇章引擎的本次 Eidos 代码版本。在创建世界 → 玩法区域导入 `mods/dist/chapter-narrative.eidos-plugin.json`，选中「篇章叙事」，按原有流程生成世界。原作或外部设定仍从原有资料入口导入。

开启内容审核并配置 KEI。首次行动、需要重评篇章或处理后台提案时，会在 ALICE 正文前调用一次 KEI；后台审核沿用现有审核流程。预生成候选也可能产生这笔用量，只有实际采用的候选才进入章节存档。准备失败时继续普通正文，不假造成功的章纲；同一行动的工具续写不反复重试。

可以与「连续阅读与剧情选择」同时使用：它负责连续阅读、镜头和选择；篇章叙事负责正式章名、章节衔接和长期经历。无需打开作者工作台，没有额外游戏面板。

已有存档缺少篇章字段仍能正常加载。**当前宿主在已开始世界中只提供同 ID 模组升级，没有通用热安装新模组入口**；本包首次安装走创建世界的现有入口，不会自动挂到所有旧世界。已经安装本插件的世界可在设置 → 篇章叙事 → 版本更新应用后续包，历史章实例与证据随世界线保留。应用旧版本前请使用匹配的存档。

## 实机重点观察

- 从眼前一件小事开场，看看设定是否通过人物处境、物件和行动体现，而不是堆世界说明。
- 提前解决核心问题，拒绝原目标，或主动离开。后续是否承认你的做法、形成有意义的收束或暂别。
- 连续进行日常合作、闲聊与相处。能否积累具体关系经历，而不是无缘由升级危机。
- 让一名配角成为焦点，再回旧地。是否接住旧承诺与共同经历，人物篇是否有资格自然成为主线。
- 同时使用连续阅读插件观看幕间。读者知道的事不能直接进入主角知识。
- 从同一节点走两个方向，再回溯、保存、重载。两条分支的章名、期待、关系记忆与后果应各自独立。

自动化用例验证状态、证据、分支和调用流程；实际文学质量、长篇节奏和模型成本仍需实机观察。报告问题时附上行动记录、前后正文、世界线节点及 ALICE/KEI 模型设置即可。

## 作者资料

世界生成阶段将当前世界的开局场面、故事线、关系群、确定真相、未知部分与后续机会写入 `gameModeConfig["chapter-narrative"]`。它们是创作材料，不能凭配置直接变成已发生事实。正式经历存于分支快照的 `chapterState`，不使用作者 UI 的私有状态。

停用时保留已有资料；停用期间的新正文保留为未分配篇章的经历，恢复后先重评。资料中的章纲和候选不会触发硬编码剧情。

重新打包：`node scripts/pack-mods.mjs chapter-narrative`。`pack.json` 使用 `guideOnly: true`，无 HTML、脚本或独立界面产物。
