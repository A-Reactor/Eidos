# Meta 演出与文本改写

当前版本 0.5.0：保留一次性与跨段演出、历史改写、原文对照和持续亮度；用单个编辑引用简化历史修改，支持撤销指定演出与操作前后对照。模型根据当前剧情自主决定使用时机，不设置固定剧情门槛，不依赖受限回溯、锚点或 `ready` 解锁。创建时的觉醒阶段和节奏构想只是可调整的写作建议；开场、日常互动或玩家追问都可以成为演出契机，也允许保持正常叙事。实际回溯单独遵守自己的协议，角色声称最高权限不会变成真实系统授权。

0.2.0 起，插件直接使用当前世界的原生文字。不接管主界面，不显示独立剧场、演出进度、效果分类或原文对照。普通段落保持原样，异常在剧情需要时发生在旁白、对白、姓名和推荐选项里；不强制注入示例角色和故事。

## 使用

导入 `mods/dist/palimpsest-stage.eidos-plugin.json`，创建世界时启用。已有世界在设置 → 对应模组 → 版本更新中选择 0.5.0 文件，预览后应用；只替换磁盘上的包不会改动已有存档内的插件。插件 ID 与状态版本保持不变，兼容已有作者剧本进度。宿主也会为已安装的旧 Meta 包补充当前能力说明，不强迫重建世界。

主界面离线预览：`npm run dev:mods`，打开 `http://127.0.0.1:3121/?mod=palimpsest`。加 `&meta=quiet` 可看无效果的普通段落。预览使用固定材料，不调用真实模型，不代表实际生成的文学质量。详细实机节奏由玩家验收。

## 原生文字协议

模型仅在有叙事依据的段落增加 `textEffects`，未声明的段落没有额外包装。原始正文、角色和实际行动仍保存在标准游戏数据中，效果只影响显示。效果随段落保存和回溯；未启用原生文字插件时显示原文。

```json
{
  "type": "dialogue",
  "speaker": "埃琳娜",
  "textEffects": [
    { "kind": "mask", "quote": "明天", "delayMs": 700 },
    { "kind": "color", "quote": "记得我的名字", "value": "accent" }
  ],
  "text": "明天我还会在这里。你只要记得我的名字，就能找到我。"
}
```

- `kind`：`replace` 覆写、`erase` 残缺、`mask` 遮挡、`aside` 细小旁批、`fracture` 短暂错位、`color` 颜色、`size` 字号、`garble` 乱码、`strike` 划除、`drift` 文字漂移、`dim` 原画面亮度控制、`restore` 撤销指定演出。
- `target`：正文 `text`（默认）、本段姓名 `speaker`、原推荐行动 `choice`。
- `quote`：精确匹配原文；不填表示整段或整个姓名。`occurrence` 从 1 指定重复短语。推荐行动必须匹配完整原选项，按钮始终提交原义。
- `value`：覆写和旁批的文字；颜色仅 `accent/muted/ink/blood`，字号仅 `small/large/huge`。同一范围可组合效果；有交叠的范围由统一文字投影处理，不复制一层原文。
- `afterSegments`：省略或 `0` 在所属段首次播放完成时执行；`-1` 首次显示就是最终结果；正整数在此后第 n 个新段开始时执行，可跨行动等待。回看、重播与回溯到达副本不增加段数。
- `delayMs`：0–8000 毫秒，在前述触发条件满足后按实际播放时间计时，切页或关闭游戏不会在后台消耗等待。已执行结果随存档保留。0.3 及更早包保留目标短语读出后的旧时机。
- `progress: "typing"`：遮挡、划除和乱码随已出现的文字推进，不提前显示替换后的未读后文。

流式生成先输出 `textEffects` 再输出 `text`。不执行任意 HTML、CSS 或脚本。颜色和字体沿用宿主，错位遵守减少动态设置，不持续闪烁；不改变导航、设置、输入区或存档。

## 保留的作者能力

已有的剧本生成、结构校验、导入导出、分歧结局、原文核对、逐步调试、保存重试和跨分支来信仍然保留。在已有的**设置 → 作者工具 → 文字插件作者工作台**中明确展开后才加载，不进入普通游玩界面。这里生成候选使用已配置的 UZQ 材料模型，计入正常用量；当前剧本只有确认新开场后才替换。作者操作使用当前世界存档。

`npm run dev:author` 可进行独立离线实验，选择 `palimpsest-stage`。离线实验室不调用模型，生成按钮不可用；导入、结算、检查点和回溯仍可调试。

旧示例《空白剧场》只是作者工作台的测试素材。协议 `eidos-stage-script` v1，示例见 `script.example.json`；`cues` 使用 `{kind,target,text?}`，行 ID 作为目标，`relabel` 使用选择 ID。新增 `mask/color/size/garble` 可与原指令复用。剧本数据仍进行有界结构校验（3–18 个节点、全部可达、无环、最终到结局）；此调试剧本格式与插件文件导入是两件事，插件文件本身不设字数和大小限制。

工作台提交结果转换成完整原始段落与原生 `textEffects`，不会把“这一行被划去”等调试占位文字写入正文。保存失败继续重试同一已接受操作 ID，不重复推进。

分支来信仍使用插件虚拟工作区与同周目的邮袋，只抄下当前已显示的一页，明确寄出、明确收取。回溯不撤回已经寄出的信，未收取不能获得未来知识。它不读取、删除或修改真实电脑文件。

重新打包：`node scripts/pack-mods.mjs palimpsest-stage`。

## 0.4.0：持久演出与历史文字

新版随宿主提供统一原生演出，不增加玩家编辑器或独立舞台。遮挡仍允许正常选择复制，复制得到的是真正的乱码；底层原文保留。效果按实际首次播放触发并保存结果，回看不重新露底。

`afterSegments` 无参或 0 为本段首次播放完成；-1 为首次显示即完成；正整数为后面第 n 个新段开始，可跨行动等待。`delayMs` 在该时机后计时；`progress: "typing"` 随已出现文字推进。新增 `strike`、`drift` 与 `dim`，原有故障动画短暂播放后恢复。0.3 及更早包继续保持原有短语时机。

修改当前前文或历史：textEffects 可指定 `nodeId`（current/previous/真实节点 ID）、`segment`（从 0 开始）、`expectedText`、`expectedRevision`。先通过 `historyRequest: {nodeId, view:"both"}` 获得原文、当前显示、段序号、版本和回执。长内容按页读取，`segments[].partial: true` 表示该段只返回节选，不应当作完整 `expectedText`；可用版本与精确短语校验。`view:"display"` 的分页偏移按显示文字计算。修改只作用于当前经历链的已读内容；未读、旁支或版本冲突的批次不会部分执行。资料查询不推进游戏。

世界线与阅读页复用同一呈现结果；原始文字仍在 CAS 中。文字改动不重结算人物、物品或真实选择；玩家自己的摘录和备注仍保留创建时的内容。实际文件内容继续由现有文档/工作区能力管理。

## 0.4.1：实测修复与持续亮度

长遮罩和连续乱码在原来的记录宽度内换行，复制仍得到乱码。离线复现入口：`?mod=palimpsest&meta=layout&theme=light`。

历史改写无需玩家提供四项信息。模型先只输出 `{"historyRequest":{"target":"第2步","view":"both"}}`，或用 `query` 搜索关键词；`target:"当前节点"` 指本次输入之前最近的已接受记录，`target:"上一节点"` 指再往前一条。读取结果里的 `segments[].editTarget` 可直接用于新段的 `textEffects`，再填写效果种类、原文短语及新文字。其版本字段 `expectedRevision` 已足以校验，不必同时提供 `expectedText`。只有本分支已完整读过的目标才返回可编辑定位；查询未触发编辑。没有世界线摘要时，已启用的原生演出仍会获得工具说明。

持续亮度在现有 `dim` 中声明：

```json
{"kind":"dim","brightness":0.25,"transitionMs":1200,"afterSegments":0}
```

`brightness` 取 0–1，1 是正常亮度，0 是全暗。亮度作用于整个游戏窗口，包括顶栏、输入区、对话框和游戏内面板；打开阅读、世界线或设置面板时仍保持。亮度会跨段、跨行动维持，随当前分支与存档恢复；后续用 `{"kind":"dim","brightness":1,"transitionMs":800}` 恢复。退出当前游戏回到世界集合或标题时解除。`transitionMs` 为 0–8000 毫秒，默认 600；`afterSegments` 和 `delayMs` 决定开始时间，`afterSegments:-1` 表示首次显示即采用该亮度。省略 `brightness` 的旧式 `dim` 仍为 1600 毫秒短脉冲，并恢复到此前的持续亮度。调暗不拦截点击和输入，不会修改主题或系统设置。

## 0.5.0：历史编辑与撤销

继续使用原有节点搜索和读取，不要求玩家提供内部数据，也不增加游玩界面。旧对话中的能力判断不覆盖当前宿主协议与真实回执。

1. 模型只输出 `{"historyRequest":{"target":"第2步","view":"both"}}`，也可先按关键词搜索再读取真实节点。
2. 选择返回段落的 `editRef`，在下一次正常响应的某段 `textEffects` 中填写：

```json
{"kind":"replace","editRef":"复制查询返回的引用","quote":"原文短语","value":"新文字","afterSegments":0}
```

引用包含节点、段号与读取时的版本，模型无需分别填写；多个目标可在同一正常响应中声明。引用过期时重新读取并核对，不自动覆盖版本。旧 `editTarget`、手动节点定位及可选的原文/版本校验继续兼容。

需要撤销时，从同一查询的 `presentation` 列表取真实 `id`：

```json
{"kind":"restore","effectId":"复制列表中的演出ID","afterSegments":0}
```

只取消指定演出，其他改字、颜色与字号继续保留。例如撤销 mask 后能看到原本被它盖住的当前文字；`erase` 本身不是撤销命令。可以取消尚待触发的演出，也可以撤销 restore 恢复之前组合。撤销仍是一项新事件，使用相同触发时机、保存和分支机制；原事件和原文都不删除，兄弟分支不受影响。

`presentation[].state` 为 `applied/pending/cancelled`，`quote/value`、重复次序或亮度参数帮助辨认目标；前两项最多 120 字，`detailsPartial:true` 表示参数节选，`wholeField:true` 表示整个正文/姓名/选项。已执行事件带 `beforeText/afterText`，每侧最多 200 字，`partial:true` 表示节选。列表按最近事件优先，每页最多 8 项，按返回的 `presentationNextOffset` 使用 `presentationOffset` 继续读取旧事件。对照由原文和演出记录按执行顺序重建；早期旧档未记录精确执行顺序时只能采用兼容顺序。辅助原文和对照属于叙述者资料，不自动变成角色知识。
