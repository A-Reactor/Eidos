# Skill: 时间线事件管理 (timeline-events)

教 ALICE 如何主动管理 KEI 生成的预设时间线事件——预告、偏离、回溯后重置。

## Part A: KEI 世界生成指南

```
## 时间线事件设计

你正在生成一个世界的预设时间线（WorldTimelineEvent[]）。除了标准的事件链外：

### 事件类型
设计两类事件：
1. **背景事件** (playerModifiable: false) — 无论玩家是否在场都会发生
2. **可交互事件** (playerModifiable: true) — 玩家的行动可以改变结果

### 事件涟漪
每个事件可以有 rippleEffects——描述此事件对世界的连锁影响。
这些涟漪会在当前 gameTime 触发（triggersAt）。

### 事件窗口
- 每个事件应该有"发现窗口"——在事件发生前多久玩家可以察觉到预兆
- 在事件的 description 中暗示预兆：
  ✓ "管家在第5天晚上10点销毁证据" → 暗示：第4-5天，管家看起来越来越焦虑
```

## Part B: ALICE 运行时指南

```
## 时间线管理

### 读取时间线
在每次行动的上下文中，你会看到"推演事件"段——列出当前时间附近（3小时内）的预设事件。

### 事件预告
在叙事中暗示即将发生的事件：
- 不要直接剧透（"管家明晚10点会去地下室销毁证据"）
- 用 NPC 行为暗示：
  ✓ "管家今天看起来格外紧张。你注意到他频繁地看钟。"
  ✓ "你看到管家往地下室的方向走了好几次，每次手里都拿着不同的东西。"
- 预告的强度随事件临近而增强

### 事件触发
当 gameTime 达到事件时间点时：
- 即使玩家不在那个场景，事件也会发生
- 在叙事中体现事件后果
- 如果玩家恰好在场 → 他们可以亲眼目睹并可能干预

### 事件偏离
当玩家的行动改变了事件的预设走向时：
- 设置 timelineDeviation: { eventId: "wt_0005", newOutcome: "管家没有销毁证据——玩家提前找到了它" }
- 在叙事中体现"世界因为你的行动而改变了"
- 受影响的后续事件可能需要调整（rippleEffects 中的内容可能不再成立）

### 回溯后的事件重置
当 WorldLine 回溯到更早的节点时：
- 时间线事件应该"重置"——因为 gameTime 回到了更早的时间点
- 之前已触发的事件变为"未触发"状态
- ALICE 应基于当前 gameTime 重新评估哪些事件即将到来
- 不要在叙事中暗示"你记得后来发生了什么"——除非玩家确实有那个 criticalFact
- 但是！如果玩家在上一个时间线中发现了某些信息（通过 criticalFacts 保留），
  他们可能做出不同的选择——这就是循环/回溯的核心乐趣
```

## Part C: KEI 审核指南

```
## 时间线审核

1. 事件触发是否与 gameTime 一致？
2. 事件偏离后的连锁反应是否合理？
3. 回溯后事件状态是否正确重置？
4. 是否有"事件空洞"——某个时间段没有任何事件也没有叙事推动？
```
