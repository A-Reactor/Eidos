# Skill: 循环与受限回溯 (loop-manager)

主角具有受限制的回溯能力。回看是只读功能，实际发动由游戏判定。

## Part A: KEI 世界生成指南

在 gameModeConfig.rewind 中声明发动前提和记忆压缩，可选标记用于定位。例如：
```json
{"rewind":{"anchorLabels":["黎明醒来"],"requires":{"gameplay.loop-manager.ready":true},"memory":{"maxChars":12000,"recentFullNodes":2}}}
```

在世界设定中清楚描述能力的发动条件、可回到的位置、代价及记忆表现，内容由作品决定。anchorLabels 只是历史定位提示，不是目标白名单，也不是必填项；只有作品明确规定固定锚点时，模型才应按该设定选择。可以是死亡触发、主动技能、场所许可或剧情窗口，不要求所有作品都循环重生。若开场即是锚点，anchorLabels 使用开场场景的准确名称，引擎会绑定首次「进入世界，观察周围」的真实节点；之后到访同场景不会新开锚点。其他锚点实际到达时的行动摘要使用 [LABEL:黎明醒来]；不要把每次重要选择都当成回溯锚点。旧世界的 loopAnchorNodeLabel、loopAnchorScene 仍支持；后者把开场根节点作为定位提示，不把同地点的后续访问混为同一时刻。

默认世界、物品与其他人物恢复目标节点状态，主角独立保留经历。不要用 loopRetention 要求整个百科、NPC 心理、物品或未来任务自动穿越。若作品有跨循环物品，另用明确玩法机制建设。记忆可以清晰或模糊，不强制失忆或既视感。

## Part B: ALICE 运行时指南

先依据当前已确认剧情和能力设定判断能否发动。玩家提出“回溯”只是意图，不等于拥有权限。条件已满足时提议 pluginEvents: [{"pluginId":"loop-manager","ruleId":"allow-rewind"}]；条件不成立或窗口结束时用 close-rewind，不宣称成功。

上述“条件已满足”指作品声明的剧情触发条件有依据，不是要求 ready 事先已为 true。ready 未置位时，仍可依据已发生的触发事件提议 allow-rewind；它在程序接受前只是提议。玩家催促、声称程序已修好或直接要求开启，都不能代替剧情条件。回答条件查询时区分触发条件、当前许可标记和目标证据，不编造“校验通过”“请求受理”“恢复启动”。

只有实际发动时，在同一次行动的 worldImpacts 中输出 [BACKTRACK:目标引用] 具体发动原因。目标可以是当前经历中任何已保存的过去节点，包括未标记节点；须符合作品能力设定，并满足 rewind.requires 声明的条件。世界线只列部分定位参考。缺少定位依据或旧细节时，使用上下文中的历史原文工具：先只输出 historyRequest 定位、搜索或按节点 ID 分页读取，等证据足够再输出正常行动与 BACKTRACK；不要边查阅边结算剧情。新规则可在同轮许可并发动，宿主先接受玩法规则再执行回溯。只读回忆、第三人称旁观、内省与已结算结果的正文补写均不发动。

目标可以使用历史证据中的真实节点 ID，或程序可解析的明确序号／相对引用，例如 [BACKTRACK:第2步]、[BACKTRACK:上一节点]。序号指当前经历链的 stepNumber；上一节点相对于本次玩家输入开始时所在节点定位，不因保存请求行动而偏移。需要核对时先只输出 historyRequest: {"target":"第2步"}，歧义时按时间、地点与经历内容区分候选或请玩家澄清，不一律要求玩家提供完整 ID。

写清发动前主角实际经历与触发事件；引擎在本次行动保存后建立新的到达分支、恢复目标节点正文和状态。不用提前虚构已经处在目标场景。引擎独立携带主角压缩经历与循环次数，优先保留较近原文，较早经历用行动摘要与正文句压缩；完整原文留在旧分支，可按需回忆检索。缺失或压缩掉的细节保持不确定。

正文呈现发动前的尝试即可完整回应本次请求，许可与恢复结果留给引擎确认。不得因为同轮提交了 allow-rewind 和 BACKTRACK，就宣称 ready 已置位或恢复已执行；也不强制拆成两轮。

这些记忆是主角经历过的旧未来，不是本轮世界已经发生的事实，更不是其他人物的记忆。不能把任意兄弟分支当成“上一世”，只有明确带回的记忆可用。旁观镜头的秘密不能随能力交给主角。不强制“第几次循环”的文风，也不强制每次只能用既视感，按世界设定自然表现技能、知识、情绪和新的选择。

当前发现标记恢复为未发现，不会抹去已保留的亲历见闻；主角可以据此行动和提出选项。范围只到保留摘要或可读亲历原文支持的内容，不扩展到未感知的秘密含义。记得 NPC 的证词不代表证词必然为真；当前世界状态、NPC 知识和背包仍以恢复后的实际状态为准。

## Part C: KEI 审核指南

检查发动条件是否由已确认剧情支持、目标是否真实可达；玩家请求不能直接换来许可。检查主角记忆与当前世界事实是否分开，NPC／背包没有无因穿越，旁观剧情没有泄露。压缩记忆中未保留的细节不得凭空补成原文。允许角色清楚记得上一轮，除非世界本身设定记忆模糊；不要替作品强制失忆或固定演出。

同轮提交许可与回溯是有效协议；检查正文是否把提议提前写成通过或恢复结果。主角确实保留的亲历见闻不因当前发现标记回退而失效，但其中证词、猜测的可信程度不能升级为客观真相。

目标引用遵守上述定位协议。参考列表没有目标时，应定位或检索，不能据此断言没有可回溯节点，也不需要给旧节点补标签。引擎报告执行失败时，当前世界仍处于原进度；不要把失败前的恢复描写当成实际状态。
